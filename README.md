# end-test

작업 세션이 끝날 때, 그 세션에서 다룬 내용을 문제로 되돌려주는 Claude Code 스킬.

에이전틱 코딩은 코드가 돌아가는 것과 내가 그것을 이해하는 것을 분리한다.
결과물은 쌓이는데 "왜 이렇게 짰는지"는 에이전트 쪽에만 남는다.
`end-test`는 그 간격을 측정한다.

```
/end-test
```

이번 세션의 대화에서 다섯 문항을 뽑아 한 문제씩 묻고, 답을 채점하고,
이해가 빈 곳을 기록한다.

## 출제

네 축에서 뽑는다.

- **설계 판단** — 이번에 내린 결정의 근거와 비용
- **장애·엣지케이스** — 이 코드가 프로덕션에서 깨진다면 어디서
- **CS 기본기** — 등장한 기술의 근본 원리
- **그냥 넘어간 지점** — 되묻지 않고 승인만 하고 지나간 곳

네 번째를 우선한다. 나머지 셋은 내가 모른다는 걸 아는 영역이고,
네 번째는 모른다는 것조차 모르는 영역이다.

## 채점

정답 여부가 아니라 설명할 수 있는가로 본다.

| | | |
|---|---|---|
| ○ | 메커니즘까지 설명함 | 다음 문항 |
| △ | 결론은 맞으나 이유가 빔 | 빠진 부분만 짚고 넘어감 |
| ✗ | 모름 또는 오개념 | 보충 설명 후 각도를 바꿔 즉시 재질문 |

△가 이 도구가 겨냥하는 상태다. 돌아는 가는데 왜인지 모르는 것.
○/✗ 이분법에서는 이게 ○으로 흡수된다.

## 기록

✗가 난 항목만 `~/.claude/end-test/YYYY-MM-DD.md` 에 남는다.
주제, 어떤 작업에서 나왔는지, 무엇을 몰랐는지, 보충 설명, 해결 여부.

레포 밖 경로다. 스킬을 공개해도 학습 이력은 로컬에 남는다.

## 설치

플러그인으로:

```
/plugin marketplace add imhyunho99/end-test
/plugin install end-test@end-test
```

직접 심링크로 (개발용):

```sh
git clone https://github.com/imhyunho99/end-test.git
ln -s "$(pwd)/end-test/skills/end-test" ~/.claude/skills/end-test
```

두 방법을 동시에 쓰면 스킬이 중복 등록된다. 하나만 고른다.

## 테스트

스킬은 에이전트가 읽는 지시서라 실행 결과를 단위 테스트할 수 없다.
대신 지시서가 지켜야 할 계약을 검증한다 — 프론트매터, 채점 3단계,
로그 경로, 그리고 공개 레포에 사적 식별자나 남의 문장이 섞이지 않았는지.

```sh
python3 -m unittest discover -s tests
```

표준 라이브러리만 쓴다. 설치할 것이 없다. pytest가 있으면 `pytest` 로도 돌아간다.

채점이 실제로 엄정한지는 이 테스트로 알 수 없다. 그건 얕게 답해보고
△가 나오는지 직접 확인해야 한다.
